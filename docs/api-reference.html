Class & Method Reference

The types that make up src/JenkinsAsService/, grouped by concern. Most units are internal static and reachable from tests via InternalsVisibleTo; the DI-injected seams are public interfaces. Signatures here are the current ones — when this page and the code disagree, the code wins.

Validation & pure policy

Small, side-effect-free units the worker composes. Each is internal static and directly unit-tested.

TypeEntry pointBehaviour
ServiceSettingsValidator Validate(ServiceSettings) Throws InvalidOperationException with an operator-facing message when Connection:Url or Secret:Value is empty, the URL is not absolute, or the URL carries no explicit port. The port check inspects the authority of the original string (skipping any IPv6 [...] literal), not Uri.IsDefaultPort, so an explicitly written :443 is accepted while an omitted port is rejected. Called from the Program.cs pre-flight and again in the worker.
JavaPathResolver Resolve(configuredPath, javaHome) Returns the full path to java.exe, trying configuredPath → javaHome → javaHome\bin. Throws when none contains java.exe.
AgentArgumentParser Parse(string?) → List<string> Splits Agent:CustomArguments on whitespace while honouring double-quoted values (spaces preserved) and escaped quotes (\" → "). Null/empty yields an empty list.
AgentTransport InitialMethod, Toggle, ShouldFallback, UsesWatchdogReconnect Transport-selection policy for Connection:Method. InitialMethod maps Auto to its starting transport; ShouldFallback is true only for Auto when a real exit happened before the stability window; Toggle flips WebSocket ↔ Https. UsesWatchdogReconnect is true for Auto only — that is what adds -noReconnect, so a failed handshake exits the process instead of the agent retrying one transport forever.
DataPaths ResolveDataDirectory, ResolveAgentDirectory, ResolveWorkDirectory Expands environment variables in Agent:DataDirectory, defaulting to %ProgramData%\JenkinsAsService, and derives the agent\ (jar cache) and work\ (Jenkins -workDir) subdirectories.

Secrets & configuration writing

ISecretResolver / SecretResolver

string Resolve(ServiceSettings settings);

Resolves the raw secret once at startup, by Secret.Mode:

  • Unprotected — returns Secret.Value as-is
  • Dpapi — ProtectedData.Unprotect (machine- or user-scope, same entropy as the writer)
  • Tpm — RSACng decrypt via the TPM Platform Crypto Provider (non-exportable key)
  • EnvironmentVariable — machine-level environment variable named by Secret.Value
  • CredentialManager — Credential Manager entry named by Secret.Value

SecretWriter

File: SecretWriter.cs. Every write goes through a temp file + File.Replace, so a hardened ACL on appsettings.json survives.

MethodBehaviour
WriteConfig(basePath, secret, mode, server, agentName?, javaPath?, dpapiScope, controllerCertThumbprint?, serviceAccount?) Processes the secret for mode (DPAPI/TPM encrypt, store env var, store credential, or leave plaintext) and writes the nested Jenkins section. Preserves other top-level sections (e.g. Telemetry) and in-section fields not passed in. With serviceAccount, hardens the file ACL to SYSTEM + Administrators + that account.
MergeConfig(basePath, ConfigMergeFields) Applies only the non-null members of ConfigMergeFields (Method, DpapiScope, ViaFile, CustomArguments, SanitizeEnvironment, AllowedEnvironmentVariables, DebugMode, CompactLog, RetainedLogs, MaxRetries), leaving everything else untouched. Backs the installer's WriteAdvanced1/2/3 custom actions.
SetDataDirectory(basePath, dataDirectory) Writes just Agent:DataDirectory. A separate call because folding it into the main custom-action command line would exceed the MSI 255-character limit.
NormalizeConfig(basePath) → (added, removed) Reconciles the file to the current schema via ServiceSettingsNormalizer.NormalizeJson, rewriting only when something changed. Never reads, resolves or rewrites the secret value. Returns the added and removed dotted paths.

ServiceSettingsNormalizer.NormalizeJson(existingJson)

File: ServiceSettingsNormalizer.cs. Pure, deterministic, no I/O. Builds a schema tree by serializing fresh ServiceSettings / TelemetrySettings POCOs (enums as strings, so defaults match the shipped appsettings.json) and returns (mergedJson, addedPaths, removedPaths): schema keys absent from the file are added at their defaults, present values are preserved verbatim, and any key or top-level section the schema does not define is dropped. Unparseable or non-object input is returned untouched, so a corrupt config is never overwritten with defaults.

UpdateSecretCommand.Run(args[, basePath])

Shared by the verbs: InstalledConfig.TryReadJenkinsSection(basePath, onError) is the one defensive read of an existing installation's appsettings.json, used by purge and grant-data-access. Both run as custom actions during uninstall or upgrade, when the file may be absent, half-written or unreadable — none of which may throw out of a custom action — and for purge the file is also the thing about to be deleted, so it is read once, up front.

File: UpdateSecretCommand.cs. The JenkinsAsService.exe update-secret CLI, dispatched from Program.cs before Serilog is initialised. Arguments are parsed by hand (no System.CommandLine dependency); returns 0 on success, 1 on error. Flag reference: Configuration → CLI: update-secret.

  • Interactive — console prompts (server / secret / mode, with masked input) live in InteractiveConfigPrompts.
  • --silent — every value from flags; the secret may come from --secret, --secret-file (deleted after reading) or --secret-env.
  • --impersonate — wraps the write in WindowsIdentity.RunImpersonated for Credential-Manager and User-scope DPAPI writes. The LogonUser P/Invoke is isolated in ImpersonationRunner.
  • --merge / --set-data-dir / --upgrade — the non-interactive installer paths, mapping to MergeConfig, SetDataDirectory and NormalizeConfig. --upgrade then preserves an existing secret or repair-writes from the supplied args; its presence check is a raw-string read of Secret:Value — no decryption — so it works as SYSTEM regardless of which identity the secret is bound to.
  • Value parsers — ParseMode, ParseDpapiScope, ParseMethod, ParseBool, ParseInt, SanitizePathArgument are internal static and tested directly.

AgentSecretFile

File: AgentSecretFile.cs. Backs Secret:ViaFile.

  • Write(directory, secret, warn?) → path of the ACL-restricted file handed to the agent as -secret @<file>. Inheritance is broken and access reduced to SYSTEM, Administrators and the writing identity — which keeps write and delete rights so the low-privilege service account can overwrite and remove its own file.
  • GrantRead(path, user, warn?) — adds a read ACE, used by the interactive launch so the session user can read the file it is told to open.
  • Delete(path?) — called from StopAsync; null-safe and never throws.

SecretRedactor

string[] BuildPatterns(string? secret);
string   Redact(string line, IReadOnlyList<string> patterns);

File: SecretRedactor.cs. Every line of the Java agent's stdout/stderr passes through Redact before it reaches a sink. Redacting only the literal secret is not enough: the value travels through a URL, a JVM argument and the controller's own error bodies before coming back on stderr, and any of those can re-encode it — a percent-encoded secret in a log file is just as disclosed as a plain one.

  • Forms scrubbed: the secret as configured, Uri.EscapeDataString, XML/HTML-escaped (& first, or it would double-escape what the later replacements introduce), and Base64.
  • Longest-first ordering — when one form contains another, replacing the longest first stops a shorter match from carving up a longer one and leaving recognisable fragments behind.
  • Ordinal comparison — a secret is case-sensitive, and a case-insensitive scrub would mangle unrelated text.
  • An empty secret yields an empty pattern array, so callers need no null-check of their own.

TpmSecretProtector

File: TpmSecretProtector.cs. Protect / Resolve against a persistent machine-scoped RSA key in the TPM Platform Crypto Provider (JenkinsAsService-AgentSecret, RSA-OAEP-SHA256), plus IsAvailable(), DeleteKey() and ResolveAccountSid(account) — the last computes the virtual service-account SID so key use-rights can be granted to the identity that will run the service. Not exercised by CI: the tests early-return when no TPM or no elevation is present.

Networking

IJarDownloader / HttpJarDownloader

Task Download(Uri jenkinsUri, string destinationPath, CancellationToken ct);

Downloads agent.jar from <jenkinsUri>/jnlpJars/agent.jar into destinationPath (the agent\ cache directory) using the named HttpClient "JarDownloader" with AddStandardResilienceHandler() — retry, circuit breaker and timeout.

  • Conditional caching. The response's freshness validator is stored in a sidecar and replayed on the next call; a 304 skips the transfer. An ETag is preferred — kept in the ETag-sidecar (agent.jar.etag) and replayed as If-None-Match. When the controller offers no ETag, its Last-Modified goes in the Modified-sidecar (agent.jar.modified) and is replayed as If-Modified-Since. That fallback is not theoretical: a controller serving /jnlpJars/agent.jar with Last-Modified and no ETag has been observed in the wild, and against one an ETag-only cache never populates — every start re-downloads the full jar. Exactly one sidecar exists at a time: writing either removes the other. A missing jar makes the sidecar be ignored, so a 304 can never leave the caller without a jar. A 200 offering neither validator is uncacheable: both sidecars are deleted and a warning is logged.
  • Atomic replace. The body is written to a temp file and moved into place, so a mid-stream failure cannot leave a truncated jar sitting behind a valid validator.
  • SHA-256 integrity. Every 200 records the jar's hash in agent.jar.sha256; every 304 re-hashes the cached jar and compares. A mismatch forces an unconditional re-download instead of launching the altered jar. This is trust-on-first-use local integrity — for upstream authenticity, pin Connection:ControllerCertThumbprint.

IConnectivityChecker / TcpConnectivityChecker

Task Check(string host, int port, int timeoutMs, CancellationToken ct);

Connects a TcpClient under a linked CancellationTokenSource (2 s in the worker), throwing InvalidOperationException with a distinct message for a timeout (OperationCanceledException) versus a refused connection or DNS failure (SocketException). The supervision loop treats that exception as "unreachable" — retry forever, never count toward MaxRetries.

AgentJar

File: AgentJar.cs. The single definition of agent.jar and its sidecars — agent.jar.etag, agent.jar.modified and agent.jar.sha256 (all derived from FileName, not spelled out again). The downloader writes this file and the worker launches it from the same directory, so the names must be identical — one constant makes that structural instead of a convention.

JarCacheValidator / ValidatorKind

enum ValidatorKind { ETag, LastModified }

JarCacheValidator? From(HttpResponseMessage response);   // strongest validator offered, or null
JarCacheValidator? Read(string cacheDirectory);          // whichever sidecar is present
string             ConditionalHeader { get; }            // If-None-Match | If-Modified-Since
string             SidecarFileName   { get; }            // agent.jar.etag | agent.jar.modified

File: JarCacheValidator.cs. The freshness token stored beside the cached jar, and the rules for round-tripping it. One file per kind, so the name on disk says which validator it holds and nothing has to be parsed to find out; Read prefers the ETag-sidecar, and a blank or missing sidecar yields null — an unconditional GET rather than an empty conditional header. Last-Modified is normalised to a UTC HTTP-date, the only form If-Modified-Since accepts.

A stored value is screened before it is replayed: control characters are rejected and the sidecar is size-capped before it is read. The value goes out through TryAddWithoutValidation, which by design checks nothing, so an embedded newline would let whatever wrote the sidecar append headers to the request — and the cache directory sits under %ProgramData% beside the build work directory, writable by the account build steps run as. An unusable sidecar degrades to a full download rather than to a malformed request.

JarCachePaths

File: JarCachePaths.cs. Every path inside the agent-binary cache — the jar, its .tmp, the hash sidecar and either validator sidecar — derived once from the cache directory and passed as a single value. Keeps the four-string parameter lists (and the repeated Path.Combine calls) out of the download path.

ProxyResolver / ProxyMode

enum ProxyMode { System, Direct, Explicit }

ProxyMode  ClassifyMode(string? proxy);
Uri        ParseAddress(string address);
string[]   ParseBypassList(string? bypass);
IWebProxy? Create(string? proxy, string? bypass);
string     ToBypassRegex(string entry);

File: ProxyResolver.cs. Turns Connection:Proxy / Connection:ProxyBypass into the proxy attached to the jar client's handler. Parsing is split out from the HTTP wiring because it is unit-testable policy, and a silently misparsed value looks exactly like an unreachable controller. Operator-facing behaviour is documented under Configuration → Proxy.

  • ClassifyMode — empty/whitespace → System (inherit the machine/WinHTTP proxy); direct or none, case-insensitively → Direct; anything else → Explicit.
  • ParseAddress — a bare host:port is given the http scheme, since that is how proxies are conventionally written. An unparseable value throws at startup, not on the first download.
  • Create — returns null for System and Direct: the first leaves the handler default alone, and the second is expressed by the caller clearing UseProxy, not by an empty WebProxy.
Why bypass entries become URI-shaped regexes

WebProxy.BypassList holds regular expressions, not wildcards, and matches them against the whole URI (https://host:8443/path) — not the hostname. A host-only pattern therefore never matches anything, silently. ToBypassRegex escapes the entry, reinstates * as [^/]*, and wraps it as ^[^:]+://<host>(:[0-9]+)?(/.*)?$, so *.corp.local matches https://jenkins.corp.local:8443/ but not https://evil-corp.local.example.com/.

CertificateThumbprintValidator

Normalize(thumbprint) strips colons/spaces and upper-cases; Matches(certificate, expectedThumbprint) compares the certificate's SHA-256 thumbprint against it. Wired in Program.cs as the RemoteCertificateValidationCallback of the jar client's SocketsHttpHandler when a thumbprint is configured — the pin replaces chain trust for that connection.

Agent process

IAgentProcessLauncher / IAgentProcess

IAgentProcess Start(ProcessStartInfo startInfo, Action<string> onOutputLine);

int Id { get; }
bool HasExited { get; }
int ExitCode { get; }
Task Exited { get; }
void Kill();                          // whole process tree; never throws

The seam that lets SupervisionLoopTests drive crash/stabilise/restart cycles with a fake process instead of a real java.exe. The production AgentProcessLauncher wraps System.Diagnostics.Process; the agent always runs in the service's Session 0.

Exit signal ownership

The exit TaskCompletionSource is captured in a local inside the launcher, not a shared field, so a late exit from a killed process cannot complete a newer process's signal — that bug caused spurious restarts.

Hardening

TypeEntry pointBehaviour
ProcessMitigations Apply(warn?) Sets Win32 mitigation policies on the service process: no remote, low-integrity or non-System32 DLL loads, and legacy extension-point injection disabled. Affects future LoadLibrary calls in this process only, not the Java child. Best-effort — never blocks startup.
EnvironmentSanitizer Apply(environment, extraAllowed) Removes every variable outside a curated allow-list (SystemRoot, PATH, TEMP, JAVA_HOME, ProgramFiles, profile paths, …) plus the caller's ;/,-separated additions, case-insensitively. Applied to the child's environment block — the service's own block, and anything in it, is not inherited by pipeline scripts.
ConfigAclHardener Harden(filePath, serviceAccount) Breaks inheritance on appsettings.json and reduces access to SYSTEM, Administrators and the service account, removing Users. Called from the update-secret write path.
DataDirectoryAcl Grant(directoryPath, serviceAccount, log) Grants the service account Modify on the runtime data directory, inheritable by its contents. Deliberately the inverse of ConfigAclHardener: that one replaces the DACL and switches inheritance off, because the config file may hold the secret; this one adds to the DACL and leaves inheritance on, so the folder keeps the inherited SYSTEM/Administrators full control while becoming writable by the agent identity. Uses SetAccessRule, not AddAccessRule, so a re-run on upgrade or repair replaces the account's entry instead of stacking duplicates. Backs the grant-data-access command.
ServiceRecoveryConfigurator Configure(serviceName, log) Sets the SCM failure actions through ChangeServiceConfig2: restart on each of the first three consecutive failures, 10 s apart, count reset after a day. The handle needs SERVICE_START as well as SERVICE_CHANGE_CONFIG, because the actions are SC_ACTION_RESTART. Backs the configure-recovery command. Neither WiX route was usable: util:ServiceConfig compiles to an architecture-suffixed native custom-action DLL that cannot be mixed across architectures in one transaction, and the core ServiceConfigFailureActions element is rejected with WIX1149 because the Windows Installer SDK documents its table as not working as expected.
UninstallCleanup IsSafeToDelete(path)
Purge(basePath, dataDirectory, report)		 Backs the purge command, invoked by the uninstall custom action. Deletes the runtime data tree and the CA-generated appsettings.json — neither is a tracked MSI file, so Windows Installer removes neither. Purge never throws: a locked log file must not fail an uninstall. IsSafeToDelete guards a recursive delete that runs as SYSTEM against an operator-supplied path, rejecting anything not fully qualified (a relative path would resolve against the CA's unpredictable working directory), drive roots, paths less than two levels deep, and well-known system folders.
SecretPurger Purge(mode, configuredValue, report) Removes the secret from wherever Secret:Mode put it: the machine-scoped TPM key, the Credential Manager entry, or the machine environment variable. Unprotected and Dpapi keep the material in appsettings.json, which the caller deletes; the other modes store only a pointer there, so deleting the config alone would leave a usable agent credential on the host. configuredValue is Secret:Value — for the pointer modes that is the target name, read before the config is deleted. Best-effort and never throws; every outcome is reported, including the per-user Credential Manager case SYSTEM cannot reach.
EventLogSourceInstaller Ensure(source, logName) Returns whether the event source is usable. The low-privilege service account cannot create one (HKLM write), so the installer pre-creates it as SYSTEM and Program.cs attaches the sink only if this returns true — with manageEventSource: false, so startup can never fail on a registry write.

Program.cs

Top-level statements. In order:

  1. CLI dispatch — CliCommands.TryResolve(args, out var command) maps args[0] to a handler and exits; anything unrecognised falls through to service mode. Deliberately before Serilog init, since Environment.Exit skips the flush block. The verb table lives in CliCommands rather than inline so it can be tested: an unregistered verb still compiles, and its only symptom is the exe silently starting in service mode — which, for a verb invoked by an MSI custom action, is a failed install. CliCommandsTests asserts by reflection that every command type declaring a Name is dispatchable. The four verbs are update-secret, purge, grant-data-access and configure-recovery.
  2. Boot config — a throwaway ConfigurationBuilder reads Logging:DebugMode, Logging:CompactLog, Logging:RetainedLogs and Agent:DataDirectory before the host exists.
  3. Serilog — rolling file sink in the data directory (10 MB, RetainedLogs kept; agent.log or agent.clef), Event Log sink at Warning+ when the source is usable, enrichers ProcessId / MachineName / EnvironmentName, and level overrides muting Microsoft, System.Net.Http and Polly below Warning.
  4. ProcessMitigations.Apply — hardens the service process itself.
  5. Host — BuildHost(args, basePath), split into four single-purpose steps:
    • Config source — AddJsonFile(Path.Combine(basePath, "appsettings.json"), reloadOnChange: true), then AddWindowsService(ServiceName = "Jenkins") and Configure<ServiceSettings>.
    • ConfigureJarDownloadClient — the "JarDownloader" HttpClient with AddStandardResilienceHandler(), plus proxy and certificate pinning. With neither configured the default handler is left alone; otherwise both are applied in one ConfigurePrimaryHttpMessageHandler callback, because a second call would discard the first handler.
    • RegisterCoreServices — singletons for IJarDownloader / IConnectivityChecker / ISecretResolver / IAgentProcessLauncher, and the LogLevelController and JenkinsAgentWorker hosted services.
    • ConfigureTelemetry — OpenTelemetry metrics when Telemetry:Enabled and an endpoint are both set; enabled without an endpoint warns rather than failing.
  6. Pre-flight validation — ServiceSettingsValidator.Validate on the bound settings; a failure logs the reason plus the config path and returns without starting the host.
  7. host.RunAsync(), with a global catch logging Log.Fatal and a finally that flushes Serilog.
Configuration is pinned to the install folder

The host's default content root is the process working directory, which for a service started by SCM is %SystemRoot%\system32. Without the explicit AddJsonFile(Path.Combine(basePath, …)) the bound settings come back empty and the service exits claiming Connection:Url is missing — while naming a config file that is fully populated. The same registration's reloadOnChange is what makes LogLevelController work; it is added last so it wins over the default source.

LogLevelController : IHostedService

static readonly LoggingLevelSwitch Switch;      // shared with the Serilog pipeline
static LogEventLevel LevelFor(bool debugMode);  // the only place the mapping is defined

File: LogLevelController.cs. Keeps Serilog's minimum level in step with Logging:DebugMode while the service runs. Diagnosing a crash-loop used to require editing the config and restarting — which destroys the state you were trying to observe and, on a build node, drops the agent mid-build.

  • Switch is static because the logger is built in Program.cs before the host (and therefore before DI) exists; both sides must share the one instance or a change never reaches the running pipeline.
  • StartAsync applies the current value, then subscribes to IOptionsMonitor<ServiceSettings>.OnChange; StopAsync and Dispose release the subscription.
  • A no-op change is ignored — OnChange can fire more than once for a single file save.
  • A real change is logged at Warning, so it reaches the Event Log too: a sudden shift in log volume needs an explanation with a timestamp.

Everything else in the config remains startup-only. See Configuration → Live debug logging.

JenkinsAgentWorker : BackgroundService

File: JenkinsAgentWorker.cs. Lifecycle, process construction, the supervision loop and metrics. The loop's invariants are described in Architecture → Watchdog & auto-recovery; this section is the method map.

Constructor

Injected: ILogger<JenkinsAgentWorker>, IOptions<ServiceSettings>, IJarDownloader, IConnectivityChecker, ISecretResolver, IAgentProcessLauncher, IHostApplicationLifetime. Creates Meter("JenkinsAsService", "1.0.0") (name exposed as MeterName for Program.cs) and two counters, jenkins_agent_restarts_total and jenkins_agent_severe_events_total — zero-overhead with no OTel listener registered.

ExecuteAsync(CancellationToken)

  1. LogStartupBanner()
  2. ValidateSettings() — re-runs the validator, warns on a non-HTTPS URL, resolves the agent name (hostname when empty), resolves the secret via ISecretResolver, resolves the data/agent/work directories, and picks the initial transport
  3. ResolveJavaPath()
  4. RunSupervisionLoop(ct) — connectivity, download and start all live inside it

A cancelled token is a clean shutdown. Any other exception is non-transient (bad config, unresolvable secret, missing Java), so it is logged and IHostApplicationLifetime.StopApplication() is called rather than faulting the host.

StopAsync(CancellationToken)

Sets _stopping before killing, so the kill-induced exit is not counted as a crash, then KillAgent(), AgentSecretFile.Delete(...), and base.StopAsync.

Process construction

  • BuildProcessStartInfo() — ProcessStartInfo with redirected stdout/stderr, no shell, WorkingDirectory = work\; then AddAgentArguments and, when enabled, EnvironmentSanitizer.Apply.
  • AddAgentArguments(...) — builds ArgumentList (never a command string): -jar <agent\agent.jar> -url <url with trailing slash> -secret <@file|value> -name <agentName> -workDir <work\>, plus -webSocket on the WebSocket transport, -noReconnect when AgentTransport.UsesWatchdogReconnect, then the parsed CustomArguments.
  • ResolveSecretArgument() — @<file> via AgentSecretFile.Write, or the raw secret when Secret:ViaFile is off.
  • LogLaunchCommand(psi) — Debug-level only, with the resolved secret replaced by *****.
  • ParseAgentOutput(line) — redacts the secret, then routes by prefix: INFO: → Information, WARNING: → Warning, SEVERE: → Error plus Interlocked.Increment on the SEVERE tally and the OTel counter; anything else → Information (Debug when DebugMode). All calls share the "{Output}" template constant.

Supervision

  • RunSupervisionLoop(ct) — while (true) with a single shutdown gate at the top (kill, then return) so an agent started by bring-up after StopAsync ran is still reaped. Snapshots _agent into a local each iteration, because StopAsync nulls the field from another thread.
  • TryBringUpAgent(ct) — one attempt: connectivity → IJarDownloader.Download → StartAgentProcess. Returns false for both "unreachable" and "download/start failed", which drives backoff but never the give-up counter.
  • ApplyAutoTransportFallback(agentActuallyExited) — delegates to AgentTransport.ShouldFallback and toggles _effectiveMethod.
  • KillAgent() — takes ownership with Interlocked.Exchange(ref _agent, null) so two threads cannot kill or dispose the same instance, then clears the SEVERE tally so a deliberate kill does not inflate the next run's report.
  • HasExceededMaxRetries(crashCount, maxRetries) and ComputeBackoffDelaySeconds(attempt, baseSec, maxSec, multiplier) — internal static pure functions (10 s base, ×2, 300 s cap).
  • UseFastTimingForTests(stabilityMs, backoffBaseSec, backoffMaxSec) — test seam that shrinks the windows to milliseconds so the whole loop runs deterministically.
