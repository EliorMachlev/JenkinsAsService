CI/CD and Security Scanning

GitHub Actions Workflows

The repository has eight workflows covering build, test, security scanning, and release automation.

.NET Build (.github/workflows/build.yml)

  • Purpose: Build and test on every push/PR to main
  • Runner: windows-latest
  • Steps: Setup .NET 10 → dotnet restore -p:RestoreLockedMode=true → dotnet build → dotnet test
  • Tests: 59 unit tests (xUnit + NSubstitute + FluentAssertions)

Release (.github/workflows/release.yml)

  • Purpose: Automated dual-architecture release
  • Triggers:
    • Tag push — any tag matching v* (e.g. v1.0.5). Version is taken verbatim from the tag name.
    • Manual (workflow_dispatch) — optional version input:
      • If provided (e.g. 1.05): used verbatim as the release version.
      • If omitted: auto-bumps the latest published non-prerelease release by +1 on the final segment, preserving zero-padding (e.g. 1.03 → 1.04).
  • Runner: windows-latest
  • Steps:
    1. Setup .NET 10 → dotnet test
    2. Resolve version (from tag, explicit input, or auto-bump via gh api)
    3. Optimized publish for win-x64 and win-x86 (R2R, compression, embedded PDB, deterministic, speed-optimized, locked restore)
    4. Build MSI installers for both architectures via WiX v5
    5. Create .7z archives (LZMA2, max compression) via 7-Zip
    6. Install WinRAR via Chocolatey → create .rar archives (RAR5 with 5% recovery record)
    7. Generate checksums.json with SHA256 hashes for all artifacts
    8. Create GitHub Release with all artifacts and auto-generated release notes
  • Tool: softprops/action-gh-release
  • Naming: JenkinsAsService_<version>_<arch>.<ext>

CodeQL Advanced (.github/workflows/codeql.yml)

  • Purpose: Vulnerability analysis across two language targets in a matrix:
    • language: actions (build-mode: none) — GitHub Actions workflow YAML files
    • language: csharp (build-mode: autobuild) — C# source code
  • Tool: github/codeql-action
  • Trigger: Push/PR to main, weekly schedule (Tuesdays 16:35 UTC)
  • Output: SARIF uploaded to GitHub Security → Code scanning results (one entry per language)

PSScriptAnalyzer (.github/workflows/powershell.yml)

  • Purpose: Static analysis of PowerShell code (full ruleset)
  • Tool: microsoft/psscriptanalyzer-action
  • Trigger: Push/PR to main, Sundays at 23:23 UTC, workflow_dispatch (manual)
  • Output: SARIF uploaded to GitHub Security → Code scanning results

Semgrep (.github/workflows/semgrep.yml)

  • Purpose: Pattern-based SAST — vulnerable code patterns, deprecated APIs, common weaknesses
  • Tool: semgrep/semgrep-action@v1
  • Trigger: Push/PR to main, Sundays at 04:38 UTC
  • Rules: p/default + p/csharp + p/secrets (community rulesets, no token required)
  • Output: SARIF uploaded to GitHub Security tab

Gitleaks (.github/workflows/gitleaks.yml)

  • Purpose: Secret and credential scanning across full git history
  • Tool: gitleaks/gitleaks-action@v3.0.0
  • Trigger: Push/PR to main, Sundays at 05:00 UTC
  • Coverage: fetch-depth: 0 — scans all commits

Dependency Review (.github/workflows/dependency-review.yml)

  • Purpose: Block PRs that introduce NuGet packages with known CVEs
  • Trigger: PRs to main
  • Tool: actions/dependency-review-action@v5
  • Database: GitHub Advisory Database (GHSA)

Trivy — SCA Full Scan (.github/workflows/osv-scanner.yml)

  • Purpose: Full-repo dependency vulnerability scan (post-merge + weekly)
  • Trigger: Push to main, weekly schedule (Saturdays 23:28 UTC)
  • Tool: aquasecurity/trivy-action
  • Databases: NVD + GitHub Advisory + OSV
  • Output: SARIF uploaded to GitHub Security tab
  • Pattern: Calls trivy-reusable.yml via uses: ./.github/workflows/trivy-reusable.yml

Trivy — Reusable Workflow (.github/workflows/trivy-reusable.yml)

  • Trigger: workflow_call with inputs scan-type (default: fs) and scan-ref (default: .)
  • Steps: checkout → trivy → upload-sarif (if: always())
  • Versioning: actions/checkout@v7, github/codeql-action/upload-sarif@v4, aquasecurity/trivy-action@v0.36.0

Dependabot (.github/dependabot.yml)

Weekly automated PRs using grouped updates to reduce noise:

NuGet (nuget)

  • serilog — all Serilog.* packages in one PR
  • microsoft-extensions — all Microsoft.Extensions.* packages in one PR
  • opentelemetry — all OpenTelemetry* packages in one PR
  • xunit — all xunit* packages in one PR
  • test-tooling — Microsoft.NET.Test.Sdk, coverlet.*, NSubstitute, FluentAssertions in one PR

GitHub Actions (github-actions)

  • All action version bumps grouped into a single weekly PR

Code Scanning Results (Security Tab)

Two workflows upload SARIF and contribute findings to GitHub Security → Code scanning:

  • CodeQL Advanced — two matrix jobs: language: actions (workflow YAML) and language: csharp (C# source via autobuild)
  • PSScriptAnalyzer — static analysis of PowerShell scripts embedded in workflow run: steps

NuGet Dependency Submission

GitHub automatically runs a platform-managed submit-nuget workflow (listed as dynamic in the Actions tab) that submits the resolved NuGet dependency graph to GitHub’s dependency graph API. This is not a workflow file in the repository — GitHub triggers it when a .csproj or packages.lock.json is present. It powers Dependabot alerts and the dependency graph view for this repo.

Action Versioning Policy

All actions use floating major-version tags — no SHA pins. Rationale: personal/low-risk repo; SHA pins add friction without meaningful supply-chain benefit at this scale.

Security Policy (Security.md)

  • Scope: JenkinsAsService executable, MSI installer, CI workflows. Jenkins/JDK/OS/third-party packages are out of scope.
  • Supported versions: Latest release only. Older versions are not patched.
  • Reporting: GitHub Private Vulnerability Reporting (preferred). No public issues for security bugs.
  • Response timeline: Acknowledge in 3 business days, assess in 7, patch within 30 days (critical/high) or 90 days (medium/low).
  • Coordinated disclosure: 90-day window, reporter can self-disclose after. Credit offered if desired.
  • Bounties: None (volunteer project).
