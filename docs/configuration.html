Configuration

Configuration File

The service reads its settings from appsettings.json, located in the same directory as the executable. The Jenkins section contains all service-specific settings.

Settings Reference

Setting Required Default Description
JenkinsURL Yes — Full Jenkins URL including port. Must include an explicit port — default ports (80/443) are rejected. Example: https://jenkins.example.com:8443
AgentName No Machine hostname The agent/node name as configured in Jenkins. Case-sensitive.
AgentSecret Yes — The JNLP secret generated by Jenkins for this agent. Case-sensitive.
JavaPath No JAVA_HOME env var Full path to the JDK/OpenJDK bin folder. Example: C:\Program Files\Java\jdk-21.0.2\bin
CustomArguments No (empty) Additional arguments passed to java.exe. Space-separated, supports quoted values and escaped quotes (\"). Example: -noCertificateCheck
DebugMode No false true to enable debug-level logging, false to disable.
CompactLog No false true to write CLEF (Compact Log Event Format) JSON to agent.clef instead of human-readable agent.log.
RetainedLogs No 3 Number of rolled log files to keep. Oldest are permanently deleted (skips recycle bin).
MaxRetries No 0 Maximum auto-recovery attempts before the watchdog gives up. 0 = infinite retries (recommended).
SecretMode No Unprotected How AgentSecret is stored/resolved. See Secret Protection Modes below.
DpapiScope No Machine DPAPI scope when SecretMode is Dpapi: Machine (any local process can decrypt) or User (only the encrypting identity). See DPAPI Scope.
ControllerCertThumbprint No (empty) SHA-256 thumbprint to pin the controller's TLS certificate for the agent.jar download. See Certificate Pinning.
SecretViaFile No true Pass the resolved secret to the Java agent as -secret @<file> (an ACL-restricted file) instead of inline on the command line, keeping it out of the process table. See Secret off the command line.
SanitizeEnvironment No true Launch the Java agent with a deny-by-default environment (curated allow-list only), preventing the service's environment block from leaking into pipeline scripts. See Environment sanitization.
AllowedEnvironmentVariables No (empty) Extra environment variable names (semicolon/comma-separated, case-insensitive) to pass through to the agent when SanitizeEnvironment is on. Example: GRADLE_USER_HOME;MAVEN_OPTS.
DataDirectory No %ProgramData%\JenkinsAsService Writable directory for runtime artifacts (agent.jar, logs, secret file, work dir), kept separate from the read-only install folder. Env vars are expanded. The MSI sets this to the chosen DATAFOLDER. See Data directory split.

JSON Format

{
  "Jenkins": {
    "JenkinsURL": "https://jenkins.example.com:8443",
    "AgentSecret": "your-agent-secret-here",
    "SecretMode": "Unprotected",
    "DpapiScope": "Machine",
    "AgentName": "",
    "JavaPath": "",
    "CustomArguments": "",
    "ControllerCertThumbprint": "",
    "SecretViaFile": true,
    "SanitizeEnvironment": true,
    "AllowedEnvironmentVariables": "",
    "DataDirectory": "",
    "DebugMode": false,
    "CompactLog": false,
    "RetainedLogs": 3,
    "MaxRetries": 0
  },
  "Telemetry": {
    "Enabled": false,
    "OtlpEndpoint": "http://localhost:4317",
    "ServiceName": "JenkinsAsService"
  }
}
Tip

The AgentName defaults to the machine hostname if left empty. This is usually the correct value unless the Jenkins node name differs from the hostname.

Validation Flow

flowchart TD
    A["Read appsettings.json"] --> B["Bind to ServiceSettings via IOptions"]
    B --> C{JenkinsURL filled?}
    C -->|No| D[Log error & stop]
    C -->|Yes| E{AgentSecret filled?}
    E -->|No| D
    E -->|Yes| F["Parse URL via System.Uri"]
    F --> G{Explicit port?}
    G -->|No / default port| D
    G -->|Yes| H[Resolve Java path]
    H --> I["Test TCP connectivity (2s timeout)"]
    I -->|Fail| D
    I -->|Pass| J["Download agent.jar (ETag cached)"]
    J --> K[Start agent + watchdog]

Java Path Resolution

The service resolves the Java executable in this order:

  1. Use JavaPath from config if set and java.exe exists at that path
  2. Fall back to JAVA_HOME environment variable root
  3. Fall back to JAVA_HOME\bin
  4. If none work → log error and stop

URL Validation

The JenkinsURL is parsed using System.Uri:

  • Must be a valid URI (parse failure → error)
  • Must include an explicit port — Uri.IsDefaultPort rejects 80/443 since Jenkins typically runs on non-standard ports
  • TCP connectivity is tested asynchronously with a 2-second timeout

Secret Protection Modes

SecretMode controls how the AgentSecret is stored and resolved at runtime.

Mode AgentSecret field contains How resolved
Unprotected Plaintext secret Returned as-is
Dpapi Base64-encoded DPAPI ciphertext ProtectedData.Unprotect (non-portable; Machine or User scope — see below)
Tpm Base64-encoded RSA ciphertext (TPM-resident key) RSACng decrypt via the Platform Crypto Provider — see below
EnvironmentVariable Name of a system env var (default: JENKINS_SECRET) Environment.GetEnvironmentVariable(..., Machine)
CredentialManager Windows Credential Manager target name CredentialManager.GetCredentials(targetName).Password
Warning

DPAPI mode binds the secret to the machine. Moving appsettings.json to another machine will fail decryption. Re-run update-secret after a machine migration.

DPAPI Scope (Machine vs. User)

When SecretMode is Dpapi, DpapiScope chooses which key protects the secret:

Scope Who can decrypt Requirement
Machine (default) Any process on the machine None — works regardless of which identity wrote the secret
User Only the identity that encrypted it The secret must be written by the service account (see below)
User-scope identity constraint

User-scope DPAPI binds the ciphertext to a single Windows identity. Because the MSI writes the config as SYSTEM, a default install always uses Machine scope. To use User scope, the secret must be encrypted by the account that runs the service:

  • Works with a password-based dedicated account — run update-secret --mode Dpapi --dpapi-scope User --impersonate --username "DOMAIN\svc" (password via the JAS_IMPERSONATE_PASSWORD env var).
  • Not compatible with virtual accounts (NT SERVICE\Jenkins) or gMSA — they cannot be interactively logged on, so they cannot run the encryption step. Use Machine scope, EnvironmentVariable, or CredentialManager for those identities.

TPM 2.0 mode

SecretMode: Tpm encrypts the secret with a non-exportable RSA-2048 key held inside the machine's TPM, via the Microsoft Platform Crypto Provider. Unlike DPAPI machine-scope — whose key is software-derivable by any local admin/SYSTEM — the TPM private key never leaves the chip, so the ciphertext is bound to this physical machine and cannot be exfiltrated even by a full administrator.

  • Protect: the elevated installer (or update-secret) creates a persistent machine-scoped key (JenkinsAsService-AgentSecret) and RSA-OAEP-SHA256 encrypts the secret into AgentSecret.
  • Resolve: the service opens the same TPM key and decrypts. Because the key is created by SYSTEM but used by the low-privilege service account, the installer grants that account use-rights on the key — pass --service-account to update-secret (the MSI does this automatically).
Requirements & binding

Requires a TPM 2.0 with the Platform Crypto Provider present. The key is bound to the machine, not to platform/PCR state, so routine firmware and Windows updates do not break decryption. Clearing/resetting the TPM or moving to another machine invalidates the ciphertext — re-run update-secret --mode Tpm there.

Certificate Pinning

Set ControllerCertThumbprint to the SHA-256 thumbprint of the Jenkins controller's TLS certificate to defend against a MITM that presents a different but chain-trusted certificate (e.g. a rogue internal CA). When set, the agent.jar download accepts the connection only if the server certificate's thumbprint matches — the pin replaces chain trust. Separators (colons, spaces) and case are ignored.

Scope of the pin

This pins the .NET agent.jar download only. The Java agent's own control-channel TLS is handled by the JVM, not .NET. To pin that connection as well, pass the controller certificate to the agent via CustomArguments (the Jenkins remoting agent accepts -cert <PEM>).

Secret off the command line

By default (SecretViaFile: true) the resolved JNLP secret is never placed on the Java agent's command line. It is written to an ACL-restricted file (inheritance broken; SYSTEM, Administrators, and the service account only) and handed to the agent as -secret @<file>. This keeps the secret out of the process table — otherwise any local administrator could read it for the agent's entire lifetime via Get-Process or WMI Win32_Process.CommandLine. The file is overwritten on each restart and deleted on service stop. Set SecretViaFile: false only if your Jenkins remoting version predates @file support.

Environment sanitization

With SanitizeEnvironment: true (default) the Java agent is launched with a deny-by-default environment: only a curated allow-list of variables the JVM and common Windows build tooling need (SystemRoot, PATH, TEMP, JAVA_HOME, ProgramFiles, …) is passed through. This stops the service's own environment block — which may carry host secrets or tokens — from being inherited by untrusted pipeline scripts that run inside the agent. If a build needs an extra host variable, add it to AllowedEnvironmentVariables (semicolon/comma-separated, case-insensitive) rather than disabling the feature.

Data directory split (binaries vs. runtime data)

The service keeps its read-only binary and its writable runtime data in two separate locations:

LocationDefaultContentsACL
Install folder C:\Program Files\Jenkins JenkinsAsService.exe, appsettings.json Read/Execute (default Program Files) — the agent account cannot write
Data folder (DataDirectory) C:\ProgramData\JenkinsAsService agent.jar (+ ETag cache), agent.log/.clef, .agent-secret, agent work dir Service account granted write (set by the MSI)

Because the install folder is not writable by the agent identity, a malicious pipeline running inside the agent cannot overwrite the service binary and wait for a restart — a local privilege-escalation / persistence vector that a single shared folder can't close (the same identity needs write for data but must not have it for the binary). The MSI sets DataDirectory to the chosen DATAFOLDER; for portable/manual deployments the service defaults to %ProgramData%\JenkinsAsService and creates it on first run.

CLI: update-secret

The JenkinsAsService.exe update-secret subcommand writes (or re-writes) appsettings.json with the secret processed for the chosen mode. Used by the MSI installer and manually.

JenkinsAsService.exe update-secret [options]
  --secret <value>       Plaintext secret (command-line)
  --secret-file <path>   Read from file (deleted after reading)
  --secret-env <var>     Read from named environment variable
  --url <value>          Jenkins controller URL
  --mode <value>         Dpapi | Tpm | EnvironmentVariable | CredentialManager | Unprotected
  --dpapi-scope <value>  Machine (default) | User  (User requires writing as the service account)
  --thumbprint <value>   SHA-256 thumbprint of the controller cert to pin (agent.jar download)
  --service-account <a>  Service account granted read on the config; hardens appsettings.json ACL
  --agent-name <value>   Node name (default: hostname)
  --java-path <value>    Java bin folder (default: JAVA_HOME)
  --impersonate          Run the write as a different user (Credential Manager / User-scope DPAPI)
  --username <value>     Username for impersonation (DOMAIN\user)
  --silent               Non-interactive (all values from flags)
Tip

In silent mode with --impersonate, provide the password via the JAS_IMPERSONATE_PASSWORD environment variable to avoid command-line exposure.

Telemetry (OpenTelemetry)

Disabled by default. Set Enabled: true to export metrics via OTLP.

Setting Default Description
Enabled false Enable OpenTelemetry metrics export
OtlpEndpoint http://localhost:4317 OTLP gRPC endpoint (Datadog agent, Grafana Alloy, etc.)
ServiceName JenkinsAsService service.name resource attribute

Exported metrics:

  • jenkins_agent_restarts_total — counter, increments on each successful agent restart
  • jenkins_agent_severe_events_total — counter, increments on each SEVERE: log line
  • .NET runtime metrics (GC, thread pool, memory) via OpenTelemetry.Instrumentation.Runtime
